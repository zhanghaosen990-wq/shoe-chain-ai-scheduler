# GitHub 协作与样本保护规格

## 目标

把当前工作区的完整版本发布到私有 GitHub 仓库，并把它固定为可恢复的基线。朋友只能在独立功能分支提交改动并通过 Pull Request 交付；仓库所有者完成本地或 CI 测试并批准后，改动才能进入 `main`。

## 必须满足

- `.env`、运行时数据、构建产物、依赖目录和临时输出不得进入 Git。
- 已有比赛说明 PDF 和当前演示数据必须保留在基线中。
- 当前版本通过 `npm test`、`npm run build` 和 Docker 镜像构建后才能发布。
- `main` 不作为日常开发分支；协作者使用 `feature/*` 分支和 Pull Request。
- `main` 的任何改动都需要通过 CI，并由仓库所有者 `@zhanghaosen990-wq` 审核。
- 当前版本使用带日期的 Git 标签固定，确保后续改动不会破坏可恢复的原始样本。

## 验收

- GitHub 上存在本次版本分支、提交和基线标签。
- Pull Request 可见完整变更和自动检查。
- `main` 开启保护规则：必须通过 Pull Request、至少 1 个批准、要求 Code Owner 审核、要求 `test` 状态检查通过、对管理员也生效（GitHub 套餐允许时）。
- 协作说明明确列出所有者与朋友各自的命令和职责。
