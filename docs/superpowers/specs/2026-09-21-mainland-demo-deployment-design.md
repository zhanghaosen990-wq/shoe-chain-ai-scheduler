# 中国大陆比赛演示部署与协作设计

## 目标

让鞋链智排在中国大陆公网环境中通过普通浏览器直接打开，优先保证比赛演示稳定；同时让前端同事可以独立优化页面，你可以继续修改后端而不互相覆盖。

## 现状与约束

- 项目是 Node.js 单体服务，`app/server.js` 同时提供静态资源和 API。
- 前端构建命令是 `npm run build`，服务启动命令是 `npm start`。
- 演示状态默认写入 `data/portal-state.json`，认证主要依赖浏览器本地存储。
- 比赛数据是虚构演示数据，不承载真实客户信息。
- 评委在中国大陆，部署必须使用中国大陆可访问的公网服务器或服务商。
- 本阶段不拆分前后端，不引入数据库，不改变业务接口。

## 选定方案

使用中国大陆云服务器运行 Docker Compose：

- `app` 容器运行现有 Node 服务；
- `caddy` 容器负责 80/443 端口、反向代理和域名 HTTPS；
- Docker volume 保存演示状态文件；
- GitHub `main` 分支作为比赛稳定版本；
- 前端和后端继续共用同一套 API 和同一个公网地址。

如果暂时没有域名，`DOMAIN=:80` 可通过公网 IP 使用 HTTP 演示；正式比赛更建议使用已解析到服务器的域名，以便自动 HTTPS。

## 数据与安全边界

这套部署只用于比赛演示。不得填入真实个人资料、真实客户订单或生产密码。DeepSeek 密钥只写入服务器 `.env`，不提交 Git。演示账号和本地身份认证不视为生产级权限控制。

## 协作边界

- 前端同事使用 `feature/frontend-*` 分支，主要修改 `app/portal/`、`app/ui/` 和样式文件。
- 后端负责人使用 `feature/backend-*` 分支，主要修改 `app/server.js`、`app/portal-store.js`、Agent 和数据接口模块。
- `main` 只接受 Pull Request，不直接在服务器上改代码。
- 前端不得擅自改变 API 字段和业务规则；后端修改接口时必须同步更新接口说明和测试。
- 每个 Pull Request 至少通过 `npm test` 和 `npm run build`。
