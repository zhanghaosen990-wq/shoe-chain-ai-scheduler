# 工厂工作台四 Tab 重构

已批准方案：简洁、高级、高效。默认概览只显示四项指标和最多三条订单，1440×900 核心内容一屏可见。订单视图为筛选栏和分页表格，评价进入抽屉；产能视图为简洁表单，导入和候选工艺按需展开；展示视图为介绍及紧凑图片网格。

导航采用 URL view=orders|capacity|showcase，默认 overview；保持品牌端下划线样式与轻动效。主操作放在顶部且随视图变化。编辑器首次访问后保留挂载，独立草稿与保存，不受轮询覆盖；刷新或离开工作台后读取保存数据。通知通过 order 参数定位订单所在页。

POST /api/portal/factory 支持 section=capacity|showcase，只校验更新对应字段；省略 section 保留整表保存。响应继续返回完整快照，本地账号同步以响应为准。新工厂可先保存展示。排期只展示真实已有状态、交期及数量。

订单详情抽屉新增“已完成订单”：仅当前承接工厂的 production 订单显示，复用 `/api/portal/order-status`，服务端验证角色、归属和当前状态，拒绝越权及重复完成。提交期间防重复，失败刷新状态；完成后仍保留在“全部”和“已完成”筛选，品牌原有确认完成能力不变。`node app/verify-factory-completion.cjs` 覆盖此流程、筛选和品牌方联系方式可见性。

实施顺序：分组保存与数据选择测试 → API 与缓存兼容 → 工作台和双表单拆分 → 通知定位与回归脚本 → 六种屏宽和首屏截图 → 独立代码复核。

验收：分组保存隔离、草稿切换/同步/失败/识别、新账号和账号隔离、导航历史/定位/筛选/分页、接拒单和品牌端回归，360/390/768/1280/1440/1920px 无溢出、键盘与减少动态效果。
